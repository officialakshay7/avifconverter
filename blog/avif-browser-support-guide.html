AVIF Browser Support in 2026: What Actually Works Where

Aug 2026 · 6 min read

AVIF has gone from an experimental format to something most modern browsers handle without a second thought — but "most browsers" isn't the same as "everything you'll ever open an image in." This guide breaks down where AVIF support actually stands, so you know when you can rely on it and when converting to JPG or PNG is the more reliable move.

Desktop browsers

All four major desktop browsers now support displaying AVIF images natively:

  • Google Chrome added AVIF support back in version 85, and it's been stable ever since across all supported operating systems.
  • Mozilla Firefox added support shortly after Chrome and has continued refining its AVIF decoder in subsequent releases.
  • Microsoft Edge, being built on the same Chromium engine as Chrome, inherited AVIF support at the same time and has kept pace since.
  • Safari added AVIF support starting with Safari 16, which shipped alongside macOS Ventura — a bit later than the other three, but solidly supported in current versions.

If you're using a reasonably current version of any of these browsers, viewing an AVIF image directly — for example, by dragging it into a new browser tab — should just work.

Mobile browsers

Mobile support largely mirrors desktop, since mobile Chrome, Firefox, and Safari share much of their underlying rendering engine with their desktop counterparts. Modern Android devices running current versions of Chrome handle AVIF without issue, and iOS devices on reasonably current iOS versions (aligned with Safari 16 and later) support it as well. Older phones stuck on outdated OS versions that can't update their browser are the main exception, since AVIF support depends on the underlying browser engine version rather than something that can be patched independently.

Where AVIF support gets patchy

Browser support tells only part of the story. A long list of software outside the browser hasn't fully caught up yet, including:

  • Older or budget design software that hasn't added AVIF import/export support, or added it only partially (able to open but not save, for instance).
  • Email clients, many of which still render AVIF attachments as broken image icons rather than displaying them inline.
  • Presentation software like some versions of PowerPoint or Keynote, where inserting an AVIF image directly may fail or produce inconsistent results depending on the exact version.
  • Print production workflows, where legacy prepress software often expects TIFF, PNG, or JPG and has no AVIF pathway at all.
  • Certain marketplaces and upload forms — e-commerce platforms, social networks, and content submission portals — that validate file types against an older allowlist that doesn't include AVIF yet.

This is the layer where most AVIF compatibility headaches actually happen. It's rarely the browser causing the problem — it's everything else in the pipeline that a browser update doesn't touch.

How to check if your specific software supports AVIF

If you're unsure whether a particular tool or platform handles AVIF, a few quick checks help:

  1. Try uploading or opening a small, non-critical AVIF test file first, rather than something important.
  2. Check the software's official documentation or changelog for mentions of AVIF support and which version introduced it.
  3. Search for the exact error message or behavior you're seeing — file format compatibility issues are common enough that others have usually run into the same one.

If the tool doesn't support AVIF and updating isn't an option (or doesn't help), converting the file to JPG or PNG first is generally the fastest path forward, since both formats are essentially guaranteed to work anywhere.

Why this compatibility gap exists

Browser vendors move relatively quickly on format support because rendering engines are actively maintained, frequently updated, and directly competing on speed and modern web feature support. Plenty of other software — especially anything used in professional, enterprise, or legacy workflows — updates far less frequently, sometimes for good reasons like stability requirements or long support cycles for business software. AVIF support in those tools tends to arrive slowly, format by format, release by release, well behind where browsers already are.

What this means practically

If you're working entirely within a modern browser environment — viewing images, uploading to a website that explicitly supports AVIF, sharing links rather than files directly — you're unlikely to run into compatibility problems today. The friction shows up specifically when an AVIF file needs to cross into non-browser software: a design tool, a print vendor, an older platform, or a colleague's outdated app.

In those situations, rather than waiting for the destination software to catch up, converting the specific file you need is usually the fastest fix. Looking ahead

AVIF's trajectory looks similar to WebP's before it: gradual, steady adoption across more and more software until the compatibility gap mostly closes. Browser support reaching this level of maturity is usually the leading indicator that broader software support follows over the next few years. Until that catches up fully, keeping a quick AVIF-to-JPG or AVIF-to-PNG conversion tool bookmarked is a practical way to sidestep the gap without giving up on using AVIF where it already works well.
